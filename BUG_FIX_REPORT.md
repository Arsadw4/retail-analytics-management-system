# Bug Fix Report

**Date:** 2026-10-10  
**Verification:** Full test suite passed after the final test-isolation fix: 32 passed, 1 upstream warning.

| Defect | Root cause | Fix applied | Main files |
|---|---|---|---|
| Protected routes could trust stale browser session state after account status, role, or server-side session changed. | Authorization depended too heavily on client session values and did not consistently validate the stored session on requests. | Validate active user and session token on protected requests, refresh role from the database, enforce idle timeout, update last-seen, and revoke invalid sessions. | `core/rbac.py`, `models/session_model.py`, `models/user_model.py` |
| Password-expired users could be redirected into a protected route loop. | The required password-change destination was not handled as a valid authenticated endpoint during the forced-change flow. | Mark the password-change screen as login-protected and route expired accounts directly to it. | `routes/auth_routes.py`, employee/account templates |
| Logout could be triggered with a state-changing GET and lacked form CSRF protection. | Navigation-based logout used a GET link. | Convert logout controls to CSRF-protected POST forms and revoke the server-side session. | `routes/auth_routes.py`, `templates/layouts/admin_sidebar.html`, `templates/layouts/admin_shell.html`, `static/css/admin_shell.css` |
| Password changes and account deactivation did not reliably invalidate existing sessions. | User/password state and session records were updated separately or not at all. | Update password/status and revoke sessions within database transactions; clear lockout state on password reset. | `models/user_model.py`, `models/session_model.py`, `routes/employee_routes.py`, `routes/admin_mgmt_routes.py` |
| Login responses could reveal whether an email existed and redirect targets could be unsafe. | Unknown-user handling differed from known-user handling, and `next` accepted unsafe URL forms. | Use a dummy password hash for unknown users, generic responses, omit raw email from logs, and reject scheme-relative/control/backslash redirects. | `routes/auth_routes.py`, `core/security.py` |
| Employee admin forms could accept invalid status/role values, allow self-deactivation, or leave user and employee records inconsistent. | Validation and linked-record updates were incomplete. | Validate role/status and employee fields; prevent self-deactivation; synchronize linked employee name/email; handle duplicate and missing records safely. | `routes/admin_routes.py`, `routes/employee_routes.py`, `models/user_model.py`, `models/employee_model.py`, `core/employee_validation.py` |
| Customer forms accepted malformed or missing data, and customer listing logged PII. | Validation differed between routes and an ad-hoc debug print remained. | Centralize normalization/validation, handle missing customer IDs, and remove the PII-producing print. | `core/customer_validation.py`, `routes/customer_routes.py` |
| Product creation could leave an orphan product when generated/provided SKU or initial stock work failed. | Product insert and dependent SKU/barcode/stock movement writes were not atomic; form validation was incomplete. | Validate category, name, SKU, price, and stock; create product and initial stock movement in one transaction with rollback on unique SKU failure. | `core/product_validation.py`, `models/product_model.py`, `routes/product_routes.py` |
| Dashboard chart period handling and empty-state checks were fragile across date ranges and repeated test runs. | Date-range interpretation and chart bucket filling were not shared; integration test assumed no historical sales in a reused test DB. | Add shared period resolution/zero-filled series handling. Make the integration test find an actually empty date before the earliest completed sale and compare populated data to a database baseline without deleting rows. | `core/dashboard_period.py`, `routes/admin_routes.py`, `models/sales_model.py`, `templates/admin/dashboard.html`, `tests/test_dashboard_period.py`, `tests/test_project_integration.py` |
| Migration/preflight checks omitted a required table and the initial migration hard-coded a database name. | The required-object inventory was incomplete and migration SQL selected a fixed schema. | Include `user_profiles` and related columns in checks; require explicit database selection instead of hard-coding a schema. | `scripts/verify_migrations.py`, `tools/db_preflight.py`, `database/migrations/001_initial_database_migration.sql`, database docs |
| Miscellaneous unused imports and inconsistent DB access patterns obscured maintenance and resource handling. | Leftover imports and one non-pooled MFA query path remained. | Remove unused imports and use the existing database context manager for MFA operations. | `models/coupon_model.py`, `models/grn_model.py`, `models/mfa_model.py`, `routes/ai_routes.py`, `routes/barcode_routes.py`, `routes/billing_routes.py`, `routes/customer_mgmt_routes.py`, `routes/hr_routes.py`, `routes/monitoring_routes.py` |

## Regression handling

The final rerun first found that the dashboard empty-state test assumed a clean database and failed when an earlier workflow test had inserted a sale. No database rows were removed. The test now selects a date before the earliest completed sale, verifies an empty response there, and compares the post-checkout chart with its pre-checkout baseline. The targeted test passed, followed by the full 32-test suite.

No external credentials were added. Password-reset email remains a documented product limitation; it was not represented as a verified flow.
